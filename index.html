Crontab vs Demonio

Dos formas de automatizar tareas en Linux: ¿cuándo usar cada una?

Temario: qué es cada uno · sintaxis · comparación · cuándo elegir · tutorial paso a paso para crear tu primer demonio.

¿Qué es crontab?

cron es un servicio que revisa cada minuto una lista de tareas programadas. crontab es el archivo (y el comando) donde cada usuario escribe esa lista.

Idea clave

"Ejecuta este comando en esta fecha/hora". El programa nace, trabaja y termina.

Ejemplos de uso

Respaldos nocturnos, limpiar archivos temporales, enviar reportes, renovar certificados.

crontab -e   # editar tus tareas
crontab -l   # ver tus tareas

Sintaxis de crontab

┌ minuto (0-59)
│ ┌ hora (0-23)
│ │ ┌ día del mes (1-31)
│ │ │ ┌ mes (1-12)
│ │ │ │ ┌ día de la semana (0-7, 0 y 7 = domingo)
* * * * *  comando
*/5 * * * *   /home/ana/script.sh     # cada 5 minutos
0 2 * * *     /home/ana/respaldo.sh    # todos los días a las 2:00
30 8 * * 1    /home/ana/reporte.sh     # lunes a las 8:30
@reboot       /home/ana/inicio.sh      # al arrancar el sistema

Límite: la mínima frecuencia es 1 minuto.

¿Qué es un demonio (daemon)?

Un demonio es un proceso que corre en segundo plano, de forma continua, sin ventana ni usuario interactuando. Su nombre suele terminar en "d".

Ejemplos reales

sshd (conexiones SSH), nginx (web), mysqld (base de datos), cron (¡el propio cron es un demonio!).

En Ubuntu

Lo gestiona systemd: lo inicia con el sistema, lo reinicia si falla y guarda sus logs.

Idea clave: "quédate corriendo y esperando trabajo".

¿Cuándo usar cada uno?

✅ Usa crontab si…
  • La tarea ocurre a horas fijas
  • Corre y termina (respaldo, limpieza)
  • Basta con precisión de 1 minuto
✅ Usa un demonio si…
  • Debe responder al instante (servidor, bot)
  • Escucha eventos, puertos o colas
  • Necesitas reinicio automático y monitoreo
Regla práctica: ¿"cada cierto tiempo hago algo"? → crontab. ¿"siempre debo estar atento"? → demonio.

Ventajas y desventajas

Crontab

👍 Simple, ligero, universal.
👎 Sin reinicio si falla, sin tiempo real, riesgo de solaparse si una tarea tarda más que el intervalo, entorno mínimo (PATH limitado).

Demonio

👍 Tiempo real, supervisado, logs integrados, control con systemctl.
👎 Más configuración, consume recursos constantemente, un error puede dejarlo en bucle.

Alternativa moderna: los systemd timers combinan horarios (como cron) con la gestión de systemd.

Tutorial: tu primer demonio en Ubuntu

Objetivo: un script que se ejecuta solo al encender Ubuntu y se queda escribiendo "Sigo vivo" con la hora en un archivo de tu carpeta personal, cada 5 segundos.

Necesitas: Ubuntu, una terminal y permisos de sudo. Todo se hace desde la terminal.
Diferencia con crontab: con @reboot el script se ejecuta una vez al arrancar y termina. Con un demonio el script se queda corriendo y, si se cae, el sistema lo levanta de nuevo.
Pasos: 1) Crear el script · 2) Dar permisos · 3) Crear el servicio · 4) Activarlo · 5) Verificar · 6) Reiniciar y comprobar · 7) Desactivarlo

Paso 1: crear el script y llamarlo mi_demonio.sh

Copia y pega todo este bloque en la terminal. Se crea en tu carpeta personal:

tee ~/mi_demonio.sh > /dev/null << 'EOF'
#!/bin/bash
# Escribe un mensaje con la hora cada 5 segundos
while true; do
  echo "Sigo vivo: $(date)" >> $HOME/mensaje_demonio.txt
  sleep 5
done
EOF

El while true es lo que lo mantiene corriendo para siempre.

Paso 2: dar permisos de ejecución

Para que Linux sepa que este archivo se puede ejecutar como un programa, corre este comando:

chmod +x ~/mi_demonio.sh

Pruébalo a mano (detenlo con Ctrl+C) y, en otra terminal, mira el resultado:

~/mi_demonio.sh
cat ~/mensaje_demonio.txt

Paso 3: crear el servicio

El servicio le dice a Ubuntu (systemd) cómo tratar tu script como demonio. Copia y pega todo el bloque:

sudo tee /etc/systemd/system/mi-demonio.service > /dev/null << EOF
[Unit]
Description=Mi primer demonio

[Service]
User=$USER
ExecStart=$HOME/mi_demonio.sh
Restart=always

[Install]
WantedBy=multi-user.target
EOF

User = quién lo ejecuta (tú) · ExecStart = qué ejecutar · Restart=always = reiniciar si se cae · WantedBy = arrancar con el sistema.

Verifica que quedó bien escrito con cat /etc/systemd/system/mi-demonio.service: debe mostrar tu usuario y tu ruta (por ejemplo /home/miguel).

Paso 4: activar el demonio

sudo systemctl daemon-reload
sudo systemctl enable --now mi-demonio

daemon-reload hace que systemd lea el archivo nuevo. enable --now lo inicia ahora y lo deja configurado para iniciar en cada arranque.

Paso 5: verificar que funciona

systemctl status mi-demonio      # debe decir "active (running)"
tail -f ~/mensaje_demonio.txt    # líneas nuevas cada 5 s (Ctrl+C sale)

Prueba de fuego: mátalo y mira cómo revive.

sudo pkill -f mi_demonio.sh
sleep 2
systemctl status mi-demonio      # sigue activo: systemd lo reinició

Paso 6: reiniciar y comprobar

sudo reboot

Cuando Ubuntu vuelva a encender, abre la terminal y ejecuta:

systemctl status mi-demonio
tail ~/mensaje_demonio.txt

Verás mensajes con la hora del arranque: el demonio se inició solo, sin que hicieras nada.

Paso 7: desactivar el demonio

Para que no se siga ejecutando al encender la computadora:

sudo systemctl disable --now mi-demonio

Si además quieres borrar todo:

sudo rm /etc/systemd/system/mi-demonio.service
sudo systemctl daemon-reload
rm ~/mi_demonio.sh ~/mensaje_demonio.txt

Comandos del ejemplo (1/2): script y archivos

Comando¿Para qué sirve?
#!/bin/bashPrimera línea del script: indica que lo ejecute el intérprete Bash.
while true; do ... doneBucle infinito: repite lo de adentro sin parar. Es lo que mantiene vivo al demonio.
echo "texto"Imprime un texto.
>> archivoAgrega lo escrito al final del archivo (con un solo > lo sobrescribiría).
$(date)Se reemplaza por la fecha y hora actuales.
$HOME y ~Tu carpeta personal (por ejemplo /home/miguel).
sleep 5Pausa de 5 segundos. Sin ella el bucle escribiría a toda velocidad.
tee archivoGuarda en un archivo el texto que recibe. Con sudo puede escribir en carpetas protegidas.
<< 'EOF' ... EOFTodo el texto entre los dos EOF se envía como contenido del archivo. Con comillas se guarda tal cual; sin comillas, el shell cambia $USER y $HOME por tus valores.
> /dev/nullDescarta la copia que tee mostraría en pantalla, para no ensuciarla.
chmod +x archivoLe da permiso de ejecución al archivo, para poder correrlo como programa.
cat archivoMuestra en pantalla el contenido de un archivo.

Resumen

  • Crontab: tareas programadas que se ejecutan y terminan.
  • Demonio: proceso siempre activo, gestionado por systemd.
  • Horario fijo → crontab. Atención constante → demonio.
  • Crear un demonio = script + archivo .service + systemctl enable --now.

Para practicar: convierte el ejemplo en una tarea de crontab y compara el resultado.
